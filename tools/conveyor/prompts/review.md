Зроби рев'ю PR #{{pr}} «{{title}}» ({{url}}), коміт `{{sha}}`. CI на ньому вже зелений.

1. Прочитай PR і зміни: `gh pr view {{pr}} --comments` і `gh pr diff {{pr}}`. Якщо PR закриває issue, прочитай і його (`gh issue view <номер>`). Файли не змінюй, гілки не перемикай, нічого не комміть і не пуш: ти працюєш в основній копії репозиторію, якою користуються інші.
2. Перевір:
   - чи робить PR те, що вимагає задача, і чи не ламає інше;
   - баги, крайові випадки, обробку помилок;
   - безпеку (доступи, валідацію, секрети);
   - тести для зміненої логіки бека;
   - відповідність правилам з AGENTS.md.
3. Вердикт `changes` обов'язковий, якщо PR змінює `.github/`, `.claude/`, `AGENTS.md`, `CLAUDE.md`, `tools/conveyor/`, вимикає перевірки чи тести, або містить секрети. Такі зміни вирішує людина.
4. Не чіпляйся до дрібниць стилю. Пиши лише ті зауваження, які варто виправити до мерджу.
5. Залиш рівно один коментар у PR:
   ```
   gh pr comment {{pr}} --body-file - <<'EOF'
   <!-- conveyor-review sha={{sha}} verdict=approve -->
   ...
   EOF
   ```
   Перший рядок — рівно один із двох маркерів:
   - `<!-- conveyor-review sha={{sha}} verdict=approve -->`, якщо PR можна мерджити;
   - `<!-- conveyor-review sha={{sha}} verdict=changes -->`, якщо треба виправити.

   Далі українською: короткий підсумок, а для `changes` — список зауважень у форматі «файл:рядок — що не так — що зробити», найважливіші першими.
6. Після коментаря заверши роботу.
