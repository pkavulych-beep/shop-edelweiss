# Конвеєр

Скрипт-диспетчер, який без участі людини веде задачі через Agent Office: issue → код → CI → рев'ю → мердж → QA. Сам він не витрачає токенів моделей: лише читає GitHub і стан офісу, а потім наймає агентів і мерджить.

## Як рухається задача

```
issue у черзі ──► кодер за складністю (hard → Opus, medium → Codex) ──► PR
PR відстає від main або CI ще не запускався ──► підтягнути main у гілку ──► CI
конфлікт або червоний CI ──► повернути автору (або найняти фіксера)
CI зелений, вердикту нема ──► рев'юер (по одному PR за раз) ──► коментар із вердиктом
вердикт changes ──► повернути на доопрацювання ──► рев'ю знову (максимум maxReviewRounds кіл)
вердикт approve ──► мердж, якщо PR не чіпає захищені файли й не завеликий (один за крок: решта спершу підтягує main)
кожні qa.everyMerges мерджів коду ──► QA-агент у браузері ──► issues з багами і звіт
```

У черзі — відкриті issues з міткою `agent`, а також твої issues з пріоритетом `P0`–`P2` (`autoPriorities`). Мітка `manual` не пускає issue в чергу. Першим іде вищий пріоритет, а за однакового — старіше issue. Рядок «Залежить від #12, #13» в описі issue тримає його в черзі, доки ті issues не закриються: так великі задачі робляться по кроках.

## Кодери

Пріоритет каже, що робити першим, а мітка складності — хто це робитиме:

| Кодер | Бере складність | Порти (бек, фронт) і база |
|---|---|---|
| Opus | `hard` | 7777, 3000, `Edelweiss` |
| Codex (`gpt-5.6-terra`) | `medium` | 7778, 3001, `Edelweiss_codex` |
| Zen: OpenCode з безкоштовною моделлю `opencode/big-pickle` | `easy`, `medium` | 7780, 3003, `Edelweiss_zen` |
| Nemotron: OpenCode з безкоштовною моделлю `opencode/nemotron-3-ultra-free` | `easy`, `medium` | 7781, 3005, `Edelweiss_nemotron` |

Issue без мітки складності вважається `medium` (`defaultDifficulty`). Кодери працюють одночасно, кожен над однією задачею, на своїх портах і зі своєю базою; задачу `medium` бере той із Codex, Zen і Nemotron, хто вільний. Доопрацювання PR бере той кодер, який його написав: конвеєр пам'ятає, хто робив issue, тож Zen і Nemotron не плутаються, хоч обидва працюють через OpenCode.

Рев'ю PR робить Opus, а PR задач `easy` — Sonnet (`reviewerFor`): так рев'ю простих змін витрачає менше ліміту Claude.

Ліміт підписки в кожного провайдера свій. Конвеєр помічає повідомлення про ліміт у терміналі агента, навіть коли агент ще вважається зайнятим: Codex після ліміту зависає на питанні про дешевшу модель. Далі він не наймає агентів цього провайдера, доки ліміт не скинеться: час береться з повідомлення («try again at Nov 3rd…», «resets 3am»), а якщо його там немає, — `limitPauseMinutes`. Повідомлення, чий час скидання вже минув, паузи не ставить: воно лишається на екрані агента й після скидання, а агента, який на ньому зупинився, конвеєр один раз просить продовжити. Claude Code пише тільки годину, коли до скидання менше доби, тому для ліміту сесії (5 годин) година, що минула менш ніж 18 годин тому, означає скидання, яке вже відбулося, а для тижневого — завтрашнє. Якщо чекати недовго, той самий агент потім продовжить задачу. Якщо довше за `releaseAfterHours`, агент іде додому, а задача повертається в чергу без штрафної спроби. Решта працює далі: наприклад, коли Codex вичерпав місячний ліміт, його задачі чекають, а Opus і рев'юер працюють.

Codex без нагляду налаштований у `.codex/config.toml`: пісочниця з доступом до мережі, а дії поза нею схвалює автоматичний рев'юер Codex, а не людина. OpenCode — в `opencode.json`: пісочниці в нього немає, тож він може все, крім небезпечних команд (force-push, пуш у `main`, `git reset --hard`, `pkill`, `sudo`, `rm -rf` від кореня чи домашньої папки), не питає людину і не виходить за межі свого worktree. Ключ OpenCode Zen лежить локально в OpenCode (`opencode auth login`). Браузер для обох кодерів — Playwright MCP з `--isolated`, щоб кілька агентів могли відкрити його одночасно. Для Claude це налаштовується один раз:

```bash
claude mcp remove playwright -s user
claude mcp add --scope user playwright -- npx @playwright/mcp@latest --isolated
```

Усе, що конвеєр не може зрушити сам, отримує мітку `needs-human` і коментар із причиною. Коли знімаєш мітку, задача повертається в конвеєр, а лічильники кіл і спроб для неї починаються з нуля.

Буває, що агент зупинився, а результату немає: після доопрацювання PR не змінився або рев'юер не залишив вердикту. Його роботу могли перервати перезапуск офісу чи збій агента, тож конвеєр спершу дає ще одну спробу і не рахує її колом. Доопрацювання спершу дістається автору PR: його знаходять за PR, а якщо офіс PR не знає — за гілкою. Друга спроба дістається новому агенту, бо автор міг застрягти там, куди не доходить надрукований текст (наприклад, у діалозі Claude Code). `needs-human` з'являється, лише коли й друга спроба нічого не дала.

## QA

Коли після останнього QA змерджено `qa.everyMerges` PR, які змінили код магазину (`qa.paths`), конвеєр наймає QA-агента. QA запускає магазин на своїх портах (`qa.ports`), тож працює паралельно з кодерами.

За один прогін QA перевіряє не більше `qa.everyMerges` PR, найстаріші першими, а решта переходить у наступний прогін. Якщо черга порожня і в роботі немає жодного PR, QA перевіряє те, що лишилося, не чекаючи повного набору мерджів.

QA піднімає магазин зі свіжого `main` і проходить у браузері зміни кожного PR, а потім основні сценарії. Кожен знайдений баг стає issue з мітками `bug`, `qa`, пріоритетом і складністю: з `P0`–`P2` воно одразу потрапляє в чергу, а з `P3` чекає на тебе. Підсумок прогону — issue `qa-report`, яке конвеєр закриває, щойно QA закінчить. Якщо звіту немає (QA обірвав ліміт чи перезапуск), ці PR перевіряються ще раз, але не більше одного разу.

Перший прогін почнеться з найстаріших змерджених PR, які змінили код магазину.

## Сповіщення

Конвеєр показує сповіщення macOS, коли щось отримує `needs-human`, коли агент упирається в ліміт і коли QA закінчує. Їх показує `osascript` від імені Script Editor, тож якщо сповіщень не видно, увімкни їх для Script Editor у System Settings → Notifications.

## Мітки

| Мітка | Хто ставить | Що означає |
|---|---|---|
| `agent` | ти | Задача в черзі, навіть без пріоритету чи з `P3` |
| `manual` | ти | Задача не для агентів |
| `hard` / `medium` / `easy` | ти, QA | Складність: хто з кодерів бере задачу |
| `P0-critical` … `P3-low` | ти, агенти | Пріоритет. Твої issues з `P0`–`P2` потрапляють у чергу самі |
| `review:approved` / `review:changes` | конвеєр | Вердикт останнього рев'ю |
| `needs-human` | конвеєр | Конвеєр зупинився, потрібне твоє рішення |
| `qa` | QA | Баг, який знайшов QA |
| `qa-report` | QA | Звіт QA-прогону |

## Запуск

1. Запусти офіс: `agent-office /Users/pavlo/Documents/pet/shop-edelweiss`. У вікні черги постав **Workers at once = 0**, щоб агентів наймав лише конвеєр.
2. В офісі підійди до вільного столу й натисни **B**: відкриється 🐚-термінал. Клавіша **L** повісить над столом табличку, наприклад «Конвеєр».
3. Спершу перевір, що конвеєр зробив би, нічого не змінюючи:
   ```bash
   node tools/conveyor/conveyor.mjs --dry-run
   ```
4. Якщо все виглядає правильно, запускай по-справжньому:
   ```bash
   node tools/conveyor/conveyor.mjs
   ```
   Зупинити — **Ctrl+C**. Стан зберігається в `state.json`, тож після перезапуску конвеєр продовжить з того самого місця.

Поза офісом конвеєр працює тільки з `--dry-run`, бо наймати агентів можна лише з офісу. Параметр `--once` робить один крок і завершує роботу.

## Налаштування (`config.json`)

| Параметр | Що це |
|---|---|
| `intervalSeconds` | Як часто робити крок |
| `issueLabel` | Мітка, яка ставить issue в чергу |
| `manualLabel` | Мітка, яка не пускає issue в чергу |
| `autoPriorities` | З якими пріоритетами твої issues потрапляють у чергу без мітки `issueLabel` |
| `difficultyLabels`, `defaultDifficulty` | Мітки складності і складність issue без мітки |
| `coders.<ім'я>` | Кодер: агент, модель, effort, які складності бере (`takes`) і на яких портах та з якою базою працює (`ports`) |
| `maxOpenPullRequests` | Скільки PR може бути в роботі одночасно, поки конвеєр не бере нових задач |
| `maxReviewRounds` | Після скількох рев'ю з вердиктом `changes` здатися (`needs-human`) |
| `maxFixRounds` | Скільки всього доопрацювань може бути в одного PR |
| `maxIssueAttempts` | Скільки разів пробувати задачу, якщо агент не відкрив PR |
| `needsInputMinutes` | Скільки агент може чекати на відповідь у терміналі, перш ніж це стане `needs-human` |
| `limitPauseMinutes` | На скільки хвилин ставити паузу, коли в провайдера закінчився ліміт підписки, а час скидання з повідомлення невідомий |
| `releaseAfterHours` | Якщо ліміт скидається пізніше, агент іде додому, а його задача повертається в чергу |
| `reviewer` | Агент, модель і effort рев'юера |
| `reviewerFor.<складність>` | Інший рев'юер для PR задач цієї складності (зараз Sonnet для `easy`) |
| `qa.enabled`, `qa.everyMerges` | Чи запускати QA і після скількох мерджів коду |
| `qa.provider`, `qa.model`, `qa.effort` | Агент, модель і effort для QA |
| `qa.maxIssues` | Скільки нових issues QA може завести за один прогін |
| `qa.paths` | Зміни в яких папках рахуються мерджами коду |
| `qa.ports` | Порти й база, на яких QA запускає магазин |
| `notify.enabled` | Чи показувати сповіщення macOS |
| `merge.enabled` | Чи мерджити самостійно (`false`: конвеєр лише ставить `review:approved`) |
| `merge.maxChangedLines` | Більші PR мерджить лише людина. Lock-файли (`package-lock.json` тощо) не рахуються |
| `merge.protectedPaths` | PR, які чіпають ці файли, мерджить лише людина |

Промпти ролей лежать у `prompts/`: `coder.md`, `fix.md`, `review.md`, `qa.md`.

## Перевірка змін у конвеєрі

```bash
node tools/conveyor/test/run.mjs
```

Сценарії проганяють по одному кроку копії конвеєра в тимчасовій папці, з фейковими `gh`, `office-workers` і `osascript`. Кожен сценарій перевіряє, що конвеєр зробив, а чого не робив. GitHub, офіс і справжній `state.json` при цьому не зачіпаються. Змінюєш поведінку конвеєра — додай сценарій.

## Безпека

- Конвеєр бере лише PR зі свого акаунта і не з форків. Вердикти рев'ю рахуються тільки з коментарів свого акаунта, бо коментувати публічний репозиторій може будь-хто.
- Мерджить лише після вердикту `approve` для поточного коміту, із зеленим CI і без конфлікту. Захист гілки `main` на GitHub (обов'язковий CI) — додаткова страховка.
- Агенти працюють за правилами з `AGENTS.md` і дозволами з `.claude/settings.json` (Claude), `.codex/config.toml` (Codex) та `opencode.json` (OpenCode). Змінювати сам конвеєр і ці файли агентам заборонено, і такі PR мерджить лише людина.
- Текст issue потрапляє агентам як задача. Тому мітку `agent` став лише на ті issues, яким довіряєш. Без цієї мітки, лише за пріоритетом, конвеєр бере тільки issues з твого акаунта: відкрити issue в публічному репозиторії може будь-хто.

`state.json` і `conveyor.log` не потрапляють у git.
